# Расшифровка голосовых сообщений WhatsApp: дизайн

Дата: 2026-10-24. Статус: на согласовании.

## Цель

Голосовое сообщение пациента расшифровывается один раз, при первом получении. Текст сохраняется и дальше используется везде вместо повторного прослушивания: в ответах ИИ на следующих ходах, в кратком анамнезе, в запросе мнения клиники (Medical Opinion Request). Координатор видит расшифровку в карточке пациента и может её исправить.

Критерии успеха:
- ИИ в WhatsApp на любом следующем ходу знает, что пациент сказал голосом.
- Анамнез и запрос мнения берут содержание голосовых из текста; аудио в Gemini повторно не отправляется, если текст уже есть.
- В переписке расшифровка не занимает места, пока её не раскроют.
- Сбой расшифровки не ломает ответ пациенту: работает прежний путь с аудио.

## Как устроено сейчас

- `app/api/whatsapp-webhook/route.ts`: аудио скачивается из Evolution, сообщение пишется как «🎤 [голосовое сообщение] (+голосовое)», байты кладутся в `MediaAssets`. Аудио уходит в Gemini только в пачке, в которую оно попало (`askGemini`, `inlineData`).
- Следующие ходы видят только заглушку.
- `app/api/leads/[id]/anamnesis/route.ts` читает текст сообщений, то есть заглушки.
- `app/api/leads/[id]/case-assistant/route.ts` заново отправляет в Gemini все голосовые лида при каждой реплике координатора.
- `components/leads/patient-card/chat-panel.tsx`: проигрыватель `<audio>`, сообщения загружаются один раз при открытии карточки, автообновления нет.

## Подход

Отдельный шаг расшифровки при получении (один дешёвый вызов Gemini на голосовое). Отвергнуты: расшифровка как побочный результат ответа ИИ (теряется при сбое ответа, усложняет схему ответа, которая уже ломалась) и расшифровка только по требованию (ИИ не помнит голосовое на следующих ходах).

## Данные

```ts
interface MessageTranscript {
  text: string;                     // дословно, на языке оригинала
  source: "ai" | "coordinator";     // кто автор текста
  model?: string;                   // модель, давшая расшифровку (для source "ai")
  at: string;                       // ISO, когда сохранена
}
```

Поле `transcript?: MessageTranscript` добавляется в `MessageDoc` (`lib/db.ts`) и в `ChatMessage` (`lib/types.ts`). Миграция не нужна: поле необязательное. Текст-заглушка сообщения не меняется.

Функции в `lib/db.ts`:
- `setAiTranscript(messageId, { text, model })`: условное обновление, не затирает исправление координатора (`"transcript.source": { $ne: "coordinator" }`).
- `setCoordinatorTranscript(messageId, text)`: безусловная запись с `source: "coordinator"`.
- `getAudioMessagesWithoutTranscript(leadId, limit)`: сообщения пациента с `media.kind === "audio"` и без `transcript`, начиная с самых свежих.

## Расшифровка (`lib/transcription.ts`)

- `transcribeAudio({ base64, mimeType, requestId })` вызывает `generateWithFallback` с отдельной инструкцией: записать речь дословно на языке оригинала (таджикский, русский, узбекский, английский, в том числе вперемешку), не переводить и не комментировать, названия лекарств, дозы и цифры записывать как слышно, неразборчивое помечать «[неразборчиво]», при отсутствии речи вернуть «[речи не слышно]». Ответ обычным текстом (без JSON-схемы), температура низкая.
- Лимит размера 15 МБ после декодирования. Больше: расшифровка пропускается, действует запасной путь с аудио.
- `startTranscription(messageId, audio)` запускает расшифровку в фоне при получении сообщения (вызывается из `processNewMessage` сразу после `saveMediaAsset`), не бросает ошибок и хранит промис в модульной карте `pendingTranscripts` (процесс один, `WEB_CONCURRENCY=1`, как у `pendingBatches`). Расшифровка идёт и для чатов с паузой ИИ.
- `waitForTranscript(messageId, timeoutMs)` ждёт промис из карты; нет записи в карте: читает из базы.
- `ensureTranscript(messageId, { requestId })`: если расшифровка есть, возвращает её; если идёт, присоединяется к ней; иначе читает байты из `MediaAssets`, расшифровывает и сохраняет. Повторный вызов не создаёт второй платный запрос.
- `ensureTranscriptsForLead(leadId, { limit = 10, concurrency = 3 })`: для запроса мнения и анамнеза, расшифровывает недостающие, остальные остаются на запасном пути.

## Единый читатель текста (`lib/transcripts.ts`, чистые функции)

- `voiceLine(text)` даёт `🎤 Голосовое сообщение (расшифровка): «…»`.
- `messageTextForModel(m: ChatMessage)`: для сообщения с `transcript` возвращает `voiceLine(transcript.text)`, иначе `m.text`.

Модель на ходе получения и на следующих ходах видит одну и ту же строку, поэтому защита от повторов и ссылки на сказанное работают одинаково.

## Поток в вебхуке

1. `processNewMessage` сохраняет сообщение и байты (как сейчас), запускает `startTranscription`, кладёт `messageId` в элемент пачки.
2. `processBatchInner` перед `askGemini` для элементов с аудио ждёт `waitForTranscript` до 20 с. Успех: `item.text = voiceLine(...)`, `item.audio` убирается (в Gemini идёт текст). Сбой или таймаут: элемент остаётся с аудио, как сейчас.
3. История для `askGemini` строится через `messageTextForModel` (в `historyText` в `lib/gemini.ts`).

Пауза накопления пачки (8 с) перекрывает бóльшую часть времени расшифровки.

## Потребители

- **ИИ в WhatsApp:** см. выше.
- **Анамнез:** `ensureTranscriptsForLead`, затем текст через `messageTextForModel`.
- **Запрос мнения (case-assistant):** `ensureTranscriptsForLead`, лента переписки через `messageTextForModel`, аудио с расшифровкой не прикладываются (как уже сделано для разобранных фото), без расшифровки прикладываются как сейчас. В инструкцию добавляется: расшифровки голосовых сделаны машиной и могут содержать ошибки, названия лекарств и дозы нужно отдельно помечать для проверки.
- **Instagram:** не затронут (вложения там не читаются).

## Интерфейс карточки пациента

Расшифровка не занимает места, пока её не раскроют.

```
свёрнуто                              раскрыто
┌───────────────────────────┐         ┌───────────────────────────┐
│ ▶ ━━━●────────────  0:23  │         │ ▶ ━━━●────────────  0:23  │
│ транскрипт ↓              │         │ транскрипт ↑              │
└───────────────────────────┘         │ Здравствуйте, у меня      │
                                      │ болит колено уже месяц…   │
                                      │ расшифровано ИИ · править │
                                      └───────────────────────────┘
```

- Под проигрывателем мелкая приглушённая ссылка «транскрипт ↓» (около 11 px, цвет `text-muted-foreground`). Это кнопка с `aria-expanded`. По нажатию текст раскрывается под ссылкой, подпись меняется на «транскрипт ↑», повторное нажатие сворачивает. Положение ссылки не прыгает.
- Раскрытый текст: `whitespace-pre-wrap`, высота не более ~10 строк, дальше прокрутка внутри блока, чтобы длинная расшифровка не растягивала чат. Блок остаётся внутри того же пузыря.
- Под текстом мелкая строка: «расшифровано ИИ» или «исправлено», рядом «править». Правка открывает поле ввода с кнопками «Сохранить» и «Отмена». Ошибка сохранения показывается рядом.
- Нет расшифровки, а байты аудио есть: вместо «транскрипт» ссылка «расшифровать». По нажатию «расшифровываю…», затем блок открывается сам. Сбой: «не удалось, повторить». Так же подтягивается расшифровка, которая появилась после открытия карточки (автообновления чата нет).
- Расшифровка есть, а аудио удалено очисткой хранилища: ссылка «транскрипт» остаётся, проигрывателя нет.
- Нет ни расшифровки, ни аудио: ничего не показывается.
- Выделение компонента: `components/leads/patient-card/voice-transcript.tsx`, чтобы `chat-panel.tsx` не разрастался.

## API

Оба маршрута под существующей авторизацией (`/api/leads/**`).
- `POST /api/leads/[id]/messages/[messageId]/transcript`: `ensureTranscript`, возвращает `{ transcript }`. Сообщение должно принадлежать лиду и быть голосовым, иначе 404.
- `PATCH /api/leads/[id]/messages/[messageId]/transcript`: тело `{ text }` (zod, 1–8000 символов), `setCoordinatorTranscript`, возвращает `{ transcript }`.

## Ошибки, приватность, стоимость

- Сбой расшифровки: запись в журнал (статус и длины), ответ пациенту идёт через аудио, как сейчас. Ограничение по размеру и таймаут обрабатываются так же.
- В журналы не попадает текст расшифровок и имена (данные о здоровье). Только идентификаторы, длины, модель, время.
- Расшифровка хранится в сообщении и переживает очистку аудио в настройках хранилища (она удаляет только `MediaAssets`).
- Стоимость: один вызов flash-модели на голосовое (аудио порядка десятков токенов в секунду). Дальше на каждом ходу и в запросе мнения идёт только текст. Старые голосовые расшифровываются лениво и один раз.

## Тестирование

- `lib/transcription.test.ts`: разбор ответа, лимит размера, присоединение к идущей расшифровке, ленивая расшифровка с лимитом и параллельностью.
- `lib/transcripts.test.ts`: `voiceLine`, `messageTextForModel`.
- `lib/db.test.ts`: условная запись не затирает правку координатора, выборка без расшифровки.
- Вебхук: успех заменяет аудио текстом, сбой и таймаут оставляют аудио, пауза ИИ не мешает сохранению расшифровки.
- case-assistant: расшифрованные голосовые не прикладываются, нерасшифрованные прикладываются, инструкция про возможные ошибки на месте.
- Эндпоинты: проверка принадлежности, валидация, права.
- Компонент `voice-transcript`: свёрнуто и раскрыто, правка, состояния без расшифровки.

## Риски и что не проверяется автоматически

- Качество распознавания таджикского и медицинских терминов нельзя проверить без реальных записей. Страховки: неразборчивое помечается, аудио сохраняется, координатор правит текст. Рекомендуется проверить на 2–3 реальных голосовых без имён после выката.
- В расшифровке теряются интонация и эмоции. Для задач бота (факты, анамнез) это допустимо.
- Карта `pendingTranscripts` живёт в памяти процесса: перезапуск в момент расшифровки приведёт к ленивой расшифровке позже.

## Вне рамок

Автоматическая расшифровка всей старой базы, перевод расшифровок на русский, расшифровка видео и круговых видео, расшифровка в Instagram.
